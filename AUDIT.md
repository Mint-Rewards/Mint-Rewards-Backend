## Recommendation for RBAC prototype implementation

- **Create new `lib/models.ts` additions (not new files), or add `lib/BrandUser.ts` / `lib/Organization.ts`** — there is no existing `BrandUser` or `Organization` model to extend; this is greenfield. Given the existing convention puts every Mongoose schema in the single `lib/models.ts` file (alongside `lib/types.ts` for interfaces), prefer following that convention rather than introducing a new per-model file pattern, unless the team wants to start splitting `lib/models.ts` up as part of this work — worth a quick decision before writing code.
- **Reuse the existing DB connection helper** — import `connectToDatabase` (default export) from `@/lib/mongodb`; it is already cached/pooled and is the pattern every other route follows. Do not create a second connection helper.
- **No brand-portal login route exists yet** — it must be created fresh (there's nothing to replace). Decide whether it lives at `/api/brands/login` or `/api/auth/brand/login` to match either the `app/api/brands/*` or `app/api/auth/*` existing groupings.
- **Decide whether to extend or supersede the flat `Role` enum in `lib/types.ts`** — RBAC will need org-scoped roles, which the current flat string enum (`"ADMIN" | "MEMBER" | ... | "BRAND"`) cannot express. Any new role/permission model should be additive (e.g. a separate `BrandUser.role` scoped to one `Brand`) rather than overloading the existing global `Role` type, since that type is shared across `User`, `Captain`, `Logistics`, and `Brand`.
- **The five unauthenticated brand-scoped routes are the actual surface this RBAC work needs to close**: `[id]/settings`, `[id]/analytics`, `[id]/deals`, `[id]/campaigns`, and `[id]` (GET). These currently trust the URL `:id` alone with no caller identity check whatsoever — the new `BrandUser` auth needs to gate these by verifying the caller's token maps to that specific brand (or to an admin), not just "any valid JWT."
- **Path alias and stack are straightforward**: App Router, repo-root `@/*` (no `src/`), npm, no Zod/next-auth installed — if either is wanted for the new work, they'll need `npm install` first.
